# Self-hosted server

The server collects sessions and native documents from your computers under one user. Each computer has its own credential and source identity. People and agents use the Pacifico CLI to search and read the combined archive.

Local SQLite, the archive and offline queries remain available. Connecting a server does not copy its full history onto your computer. Remote searches return `pacifico://` identifiers, which readers fetch on demand.

## Deploy

From the repository root:

```sh
cp apps/server/.env.example apps/server/.env
```

Set `POSTGRES_PASSWORD` to a random hexadecimal password, for example one generated by `openssl rand -hex 32`. Set `PUBLIC_URL` to the URL clients will use. Then run:

```sh
docker compose --env-file apps/server/.env -f apps/server/compose.yml up -d --build
```

The Compose stack runs Bun and PostgreSQL 17. The `postgres_data` volume stores snapshots, previous uploaded versions, search indexes, users and hashed credentials. PostgreSQL has no published host port. The HTTP service binds to `127.0.0.1:8787` by default. Set `SERVER_PORT` to change the host port.

Containers have memory, CPU, process and log limits, read-only root filesystems and restricted Linux capabilities. PostgreSQL only joins an internal network shared with the API. The API runs as an unprivileged user. For deployments with mounted secrets, `DATABASE_URL_FILE` takes precedence over `DATABASE_URL`; the file must be readable by UID 10001. Use a database role that owns only Pacifico's database and cannot create users or other databases.

For access from other computers, put the service behind your HTTPS reverse proxy or a private network. Set `BIND_ADDRESS` to the server's private interface when necessary. If your reverse proxy is another container, connect it to the Compose network and proxy to `server:8787`. The proxy must forward `Authorization` and support requests up to the upload limit. Check readiness at `/health`.

An SSH tunnel can keep the API off public interfaces:

```sh
ssh -N -L 127.0.0.1:18787:127.0.0.1:8787 pacifico-tunnel@your-server
```

Connect the CLI to `http://127.0.0.1:18787`. Restrict the tunnel account to local forwarding to `127.0.0.1:8787`, with no shell, PTY, agent forwarding or remote forwarding. Keep SSH host-key verification enabled. The loopback HTTP connection travels to the server inside SSH encryption.

## Add your computers

Create one credential per computer, using the same username:

```sh
docker compose --env-file apps/server/.env -f apps/server/compose.yml run --rm server credential emersoftware sync Mac

docker compose --env-file apps/server/.env -f apps/server/compose.yml run --rm server credential emersoftware sync Desktop
```

Each command prints a secret once. Use the corresponding secret on that computer. Do not reuse one device credential on different computers.

On the Mac, connect without putting the token in shell history:

```sh
read -s PACIFICO_TOKEN
printf '%s' "$PACIFICO_TOKEN" | pacifico remote connect https://pacifico.example.com --token-stdin
unset PACIFICO_TOKEN
pacifico remote sync
pacifico daemon start
```

`remote sync` imports and uploads once. The daemon repeats import and upload every 30 seconds on macOS. On other systems, schedule `pacifico daemon run` with the operating system's scheduler.

For a trusted private network using HTTP, add `--allow-http`. Loopback HTTP works without that flag. Redirects are rejected so credentials cannot be forwarded to another endpoint.

The endpoint, credential and assigned device identity are stored in `remote.json` under Pacifico's data directory with mode `0600`. `pacifico remote status` shows the endpoint and identity without the secret. `pacifico remote disconnect` removes that configuration and retains both archives.

## Use the CLI

Install Pacifico in the environment where the agent runs and connect it with `pacifico remote connect`, using the steps above. Pancora and other agents invoke the same CLI commands as any computer:

```sh
pacifico remote search "authentication"
pacifico remote read pacifico://DEVICE_UUID/SOURCE_KEY --format messages --limit 20
pacifico remote context /original/project/path
pacifico remote documents "deployment"
pacifico remote documents --id pacifico://DEVICE_UUID/DOCUMENT_KEY
```

Session reads default to a digest. Use `--format messages` with `--offset` and `--limit` for full messages, or `--format events` for original records. Event responses include a `next` cursor; pass its `offset`, `characterOffset` and `version` as `--offset`, `--character-offset` and `--version` to continue.

Document search returns native memories, instructions and artifacts. Read a returned identifier with `documents --id`; document offsets and limits count characters. These commands only query the server and do not import local harness files or install agent integrations.

For literal search and activity across computers:

```sh
pacifico remote search "connection refused" --mode literal --tool codex
pacifico remote context --mode activity --start-date 2026-09-01 --end-date 2026-09-09
pacifico remote --help
```

Queries print a single JSON result to stdout. Failures print to stderr and exit with status 1. Pancora uses this shell interface without a separate Hermes configuration or a special server role.

## Optional MCP clients

The server also exposes `/mcp` with the same four tools: `search_sessions`, `read_session`, `get_context` and `native_documents`. Remote tools expose no filesystem resources on the server and cannot read arbitrary server paths.

Local MCP queries include local and remote results when connected. The remote half excludes the current device, because its archive is already available locally. Session results alternate between the two search engines; PostgreSQL and SQLite relevance scores are not directly comparable. Remote results include their device name, device ID and original path. They have no local resume command.

Use `scope: "local"`, `"remote"` or `"all"` to choose the source. `device` accepts a remote device UUID. Project filters on the server match the original working-directory path exactly; paths from different machines are not guessed to be the same repository.

If the server is unavailable, combined queries return local results with `remote.available: false`. An explicitly remote query returns an error. Remote session and document identifiers route to the server automatically.

## Synchronization and retention

The durable local archive is the upload queue. Each pass compares its snapshots with the server inventory and sends only changes. A local checkpoint skips reading and hashing unchanged transcripts. A successful retry of the same snapshot creates no duplicate version. Concurrent updates use the previous server hash as a precondition, so a delayed request cannot replace a newer snapshot. A conflict is retried on a later pass.

Sync sends archived conversations and native memory, instruction and artifact documents. It never uploads live database files or invents memories. Deleting a harness source or clearing the local search cache does not delete its remote archive. A new device credential creates a new source identity even if native session IDs or paths match another computer.

The server preserves every successfully uploaded version. Changes that happen entirely between two daemon passes are not separately captured. Search and reading use the latest uploaded snapshot. Disconnecting or revoking a credential does not delete archived data.

Uploads accept up to 128 MiB per request, including the JSON envelope. Change `MAX_UPLOAD_BYTES` in the server environment if required, and match the reverse proxy limit. Failed uploads remain in the local archive for retry. Full-text search indexes bounded overlapping chunks to support large transcripts; terms must match within a chunk. Literal and regex searches inspect full messages. Regex queries have a database timeout. Record pagination preserves the original raw content.

## Back up and restore

All durable server data is in PostgreSQL. Back it up with:

```sh
docker compose --env-file apps/server/.env -f apps/server/compose.yml exec -T db pg_dump -U pacifico -d pacifico -Fc > pacifico.dump
```

Restore a backup while the server is stopped. This replaces the current database tables:

```sh
docker compose --env-file apps/server/.env -f apps/server/compose.yml stop server
docker compose --env-file apps/server/.env -f apps/server/compose.yml exec -T db pg_restore --clean --if-exists --exit-on-error -U pacifico -d pacifico < pacifico.dump
docker compose --env-file apps/server/.env -f apps/server/compose.yml start server
```

Keep the dump private: it contains conversation content and credential hashes. A normal `docker compose down` retains the volume. `down -v` deletes it.

To revoke a credential, pass the token through stdin:

```sh
printf '%s' "$PACIFICO_TOKEN" | docker compose --env-file apps/server/.env -f apps/server/compose.yml run --rm -T server revoke
```

Create a new credential to replace it. A new sync credential represents a new device; existing device snapshots remain searchable. There is no public signup or account administration endpoint. Administration requires access to the deployment.

Credentials normally belong to a computer and allow uploads and queries. For any client that should only query the archive, an optional read-only credential uses the same CLI connection:

```sh
docker compose --env-file apps/server/.env -f apps/server/compose.yml run --rm server credential emersoftware read
```
